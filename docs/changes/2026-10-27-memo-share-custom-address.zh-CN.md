# 单篇笔记分享链接的自定义地址

[English](2026-10-27-memo-share-custom-address.md)

## 问题与结果

实现 [Issue #691](https://github.com/tianma-if/edgeever/issues/691)。单篇笔记分享链接固定为 `/share/<43 位随机令牌>`，安全但难以口述、输入或记忆。现在所有者可以在分享对话框中为已开启的笔记分享设置可选的自定义地址，例如 `/share/meeting-notes`。随机令牌链接继续有效，已经发出的链接和不认识新字段的客户端都不受影响。

## 行为

| 编号 | 行为 | 验收 |
| --- | --- | --- |
| S01 | Migration `0081` 为 `memo_shares` 新增可空的 `slug` 列及部分唯一索引，并新增 `memo_share_slug_claims` 表。现有记录保留令牌、密码和解锁状态，`slug` 初始为 `NULL`。 | 升级包含公开分享和密码分享的旧数据库后，两者仍可通过令牌访问。 |
| S02 | `PATCH /api/v1/memos/:id/share` 在 `passwordProtected` 之外接受 `slug`（字符串或 `null`），二者至少提供一个。地址会去除首尾空白并转为小写，长度 3–40，仅允许 `a-z`、`0-9` 和中间的单个连字符，`notebook` 为保留字。非法输入返回 400；实例内其他分享已使用的地址返回 409 `share_slug_taken`。地址由首个占用它的工作区记录在 `memo_share_slug_claims` 中，即使清除地址或撤销分享也不会释放给其他工作区，避免他人接管已经发出的链接。 | API 测试覆盖合法、非法、保留、重复、未变化和空请求，以及地址释放后其他工作区的占用尝试。 |
| S03 | 公开笔记路由以及服务端渲染的 `/share/<地址>` 页面和 `/share/<地址>.md` 将令牌或自定义地址解析到同一分享。查找时只将自定义地址转为小写，因此 `/share/Meeting-Notes` 可打开 `meeting-notes`；令牌仍区分大小写。受密码保护的笔记不会出现在 HTML 和 Markdown 中。密码门禁、频率限制和附件校验不变。解锁 Cookie 的作用域为访问者使用的地址。公开笔记之间的链接优先使用自定义地址。 | API 测试通过自定义地址解锁后读取笔记和附件；令牌链接仍可用。分享页测试覆盖 HTML 与 Markdown 中的自定义地址、大小写混合以及受密码保护的自定义地址。 |
| S04 | 修改或清除地址会立即使旧地址失效；撤销分享会使两者同时失效。 | API 测试确认失效地址返回 404。 |
| S05 | Web 分享对话框新增“自定义地址”字段，带校验、保存操作和带 Tooltip 的移除操作。字段内容一旦变化，“地址已被使用”提示即清除。对话框中的链接、复制操作以及设置中的分享列表在设置后使用自定义地址。所有已发布语言均有文案。 | 类型检查与 Web 构建；在运行中的应用里手动检查。 |

Android 与 iOS 继续显示仍然有效的令牌链接，之后可以再接入 `slug` 字段。

## 风险与回滚

最坏情况：较短的自定义地址比随机令牌更容易被猜到，因此提示文案会说明这一点，密码保护依然可用。回滚应用后新增列保留，自定义地址不再解析，令牌链接继续有效。不修改任何已有 Migration。
