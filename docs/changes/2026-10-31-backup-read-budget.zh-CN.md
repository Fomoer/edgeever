# 备份分页读取预算与网络诊断

## 问题与范围

备份分页原先在每页读取前后各执行一次完整快照计数，扫描笔记、修订、资源、笔记本及提示词。4,199 条笔记需要 168 个默认分页；按实测每次计数约读取 16,420 行计算，仅分页校验就需要约 552 万行读取，可能耗尽 D1 免费每日读取额度，并使其他数据库请求中断。

API 现在对每页校验仅按工作区主键读取实例身份与事务性备份版本号。完整计数保留在导出开始和完成时使用的快照接口中。分页前后两次检查均保留，包括组装分页结果后的检查。协议版本 1、响应字段、归档格式与 Migration 保持原样，API 部署后已安装客户端即可使用修复。Cloudflare 与自托管共用同一路由代码。

桌面请求诊断新增请求方法、不含查询参数的路径、耗时，以及最多八个底层网络错误码。异常链遍历有数量限制，仅记录符合错误码格式的字符串，不记录任意错误消息、地址、请求头或堆栈。此变更只增加诊断，不增加重试，也不改变恢复写入。

## 风险与回滚

主要风险是备份一致性：轻量检查若实现错误，可能接受导出期间变更的数据。现有事务内递增版本号和工作区身份仍作为判断依据；过期分页及分页组装期间发生变更，仍返回 `backup_source_changed`。撤销代码即可恢复原行为，不需要数据库迁移。

## 验证

- 回归测试先复现分页期间执行 26 次全量计数，修复后遍历全部三类数据时为零次；开始、结束快照仍保留计数。真实 Schema 升级夹具保留已有笔记及旧导出调用方。
- 分页组装期间修改修订号或工作区身份，均返回 HTTP 409；现有工作区隔离、权限、归档完整性、摘要、取消与恢复测试通过。
- 备份 API、管理器、IPC、线程相关测试 76 项通过；恢复、JSON/ZIP64 与加密容器测试 31 项通过。
- 从已安装应用提取真实已发布 v2.16.0 备份线程，SHA-256 为 `2b7c074846f2cb37a30fd245cc460aca1af406266a6ac5ac306f249ee3c882a1`。使用隔离数据库，普通及加密归档的“旧导出／新恢复”“新导出／旧恢复”均通过，包括关闭源服务后逐字节检查附件；使用已安装 Electron 44.7 / Node 24.21 运行时再次通过上述验证。
- 真实本地 HTTP 连接断开后，请求诊断会保留底层传输错误码，并保持原备份失败结果；普通 Node 测试运行时与已安装 Electron Node 运行时均通过。管理器测试验证诊断脱敏。
- `bun run typecheck`、`bun run typecheck:mobile`、`bun run build:web` 均通过。

修复验证未扫描生产数据库。部署后的真实 D1 读取量、Windows/Linux 原生运行仍未验证。修复不会补回已耗尽的当日额度，先前历史故障的具体底层传输原因仍未知。
