# 全量计数查询审计

## 范围与修复

在备份读取预算修复之后，检查 API 聚合查询及其 Web、Android、iOS 和桌面端调用方。重点处理分页或轮询时重复扫描全集计数，以及只为判断存在性而计数的路径；需要精确结果的统计和并发保护仍然保留。

| 路径 | 原行为 | 修复 |
| --- | --- | --- |
| 同步首次拉取 | 每页重新统计全部笔记并聚合笔记本 | 新客户端仅首批请求元数据；后续页保留快照游标和身份信息。 |
| 旧版 JSON / Markdown 导出 | 每页重算导出集合总数 | 首批总数供进度使用；后续页多取一行判断是否结束，不加载预读行的附件和历史版本。 |
| 笔记列表与搜索 | 后续页和有限条数的候选建议也统计全部匹配项 | 支持省略总数；列表仅首批计数，笔记链接及陪伴建议跳过计数。同时保留远程分页的不透明游标。 |
| 删除笔记本前置检查 | 为拒绝非空删除而统计全部有效笔记 | 改用带索引的 `LIMIT 1` 存在性查询；保留原子删除中的目录树并发保护。 |
| 任务历史轮询 | 每 15 秒重算全部保留记录；过期清理缺少工作区与时间索引 | 迁移 `0084` 回填工作区和任务计数，并通过事务内触发器维护；轮询按主键读取精确总数。补充过期清理和历史排序索引。 |

旧客户端的默认 API 响应仍包含总数和同步元数据。新客户端也兼容旧服务端每页返回元数据。插件笔记查询继续要求精确总数。省略后续页总数不会覆盖首批进度估计，也不会产生无效缓存计数。

## 保留的聚合

- 显式请求的工作区、存储、用户、标签和笔记本统计，以及备份开始和结束时的快照计数：调用方需要精确结果。
- 陪伴记忆、操作及轮次、扩展、公开表单待处理提交、海报渲染等有界容量和配额检查：计数用于限制数量，部分参与原子写入。
- 清空废纸篓的结果计数及笔记本递归树计数：用于报告影响数量或保护并发删除。
- 本地 SQLite 计数：不消耗 D1 读取额度，调用方仍需要总数。本次没有把所有聚合都改成持久化计数器。

## 风险与回滚

分页协议处理错误可能漏数据或破坏进度。回归测试覆盖分页终止、预读行隔离、附件、选择导出、搜索和不透明游标。

任务计数涉及持久化结构。迁移 `0084` 建立索引并一次性回填，会消耗数据库读写。触发器测试在插入、忽略重复领取、更新、任务和工作区移动、级联修改、删除及事务回滚后，将持久化计数与真实统计逐项比较。正常历史查询不准备 `COUNT` SQL；罕见的父记录身份变化会重新统计受影响计数。

代码可回滚到原计数查询，同时保留新增字段、索引和触发器。不得修改或删除已经执行的迁移。本次审计未执行生产迁移、部署或生产负载测试。

## 验证

- Web/API 与 Android 必需的 TypeScript 检查、Web 生产构建。
- 项目完整测试、Rust 单元测试、重新构建后的桌面侧车测试及插件同步集成。
- 在隔离的已迁移 SQLite 上对比实际 v2.16.0 与当前同步接口；实际新旧 Swift 数据模型分别解码对应响应。
- 在旧结构上使用实际 v2.16.0 任务写入接口，再执行 `0084`，并交替通过新旧接口写入和读取：总数保持准确。
- iOS 模拟器目标的 build-for-testing 构建与本机 Swift 解码验证。未运行 iOS 真机/UI 或 Android USB 真机验证，未测量生产性能。
