# Issue 606 目录驱动的本地化（Web 与桌面端）

[English](2026-10-30-catalog-driven-i18n-web.md)

需求见 [Issue #606](https://github.com/tianma-if/edgeever/issues/606)，说明见[本地化指南](../i18n.zh-CN.md)。

## 问题与结果

多处界面通过比较语言字符串选择文案，只覆盖中文和英文，新增语言需要改代码。现在文案统一从按语言代码索引的目录读取，覆盖全部五种语言（zh-CN、en-US、ja、pl、ru）。Android 与 iOS 不在本次范围，由后续 PR 处理。

## 行为

| 编号 | 行为 | 验收方式 |
| --- | --- | --- |
| L01 | 桌面端对话框（页面崩溃、启动失败、更新就绪、安装、切换实例）、应用与编辑菜单、Windows“发送到”标签、备份通知和截图笔记标题支持全部五种语言。此前日语和俄语用户看到的是英文菜单。 | `desktop-copy.test.mjs`：各语言键和占位符一致，解析结果与共享解析器一致；`edit-context-menu.test.mjs` 覆盖五种语言的菜单键一致性。 |
| L02 | Web 错误页（笔记、页面、AI 侧栏、移动端编辑器）使用应用内选择的语言，而不是系统或浏览器语言；应用语言就绪前显示英文。此前波兰语和日语用户在移动端编辑器错误页看到的是中文。 | `error-screen-copy.test.mjs`；五种目录均包含 `errorScreens` 键。 |
| L03 | AI 伙伴回复及发现功能的回复语言覆盖全部五种，含俄语。服务端接受 `ru`；为兼容旧服务端，俄语界面的客户端仍发送 `en-US`，俄语消息按文字系统识别。 | Schema 接受 `ru`；逐语言回复测试及西里尔字母识别。 |
| L04 | 图表类型标签和行内字段标签（`[due:: …]`、优先级）随应用语言显示，覆盖全部五种语言；此前日语用户看到中文图表标签。仅有中英文版本的内置内容（印象笔记迁移指南、演示笔记本、示例）由同一个辅助函数选择：中文界面用中文，其他语言用英文——此前日语、波兰语和俄语用户拿到的是中文指南和演示笔记本。 | `inline-fields.test.mjs`、`bilingual-content-locale.test.mjs`；新增 `inlineField` 目录键。 |
| L05 | 共享目录旁的 `hardcoded-locale-guard.test.mjs` 拒绝 i18n 代码以外新增的语言比较。每个例外（字幕轨道、示例数据、中文序数、兼容映射）都附有原因。 | 测试在当前代码上通过，注入 `locale === "pl"` 时失败。 |

## 风险与回滚

仅涉及文案：无数据、API 契约、存储或迁移变化。伙伴 schema 额外接受 `ru`（更宽松，旧客户端不受影响）。回滚：撤销本次改动。

未验证：Windows 与 Linux 桌面端的交互检查；日语和俄语翻译未经母语者审校。
