# Issue 701：备份恢复资源的 XSS 防护

[English](2026-10-28-restore-resource-xss.md)

## 问题与目标

[Issue #701](https://github.com/tianma-if/edgeever/issues/701) 指出恢复接口接受 `kind=image` 与 `mimeType=text/html` 的组合，而资源响应相信 `kind` 并允许内联渲染。修复写入时的不一致，同时阻断已有异常资源的读取风险。在独立工作区基于官方 `main` 的 `b8496806` 实施。

影响范围是 Cloudflare 和 Docker 共用的 API 资源恢复及响应头。旧备份若明确把图片标为 HTML 等不相容类型，会被拒绝；合法旧备份必须仍可恢复。保留既有的可空 MIME 契约和未知/二进制回退，未知类型转为下载而非内联渲染。HTML 等普通附件仍可下载。不迁移或删除现有数据。回滚只需回退代码，无需改写资源；回退也会重新引入漏洞。原生平台运行及部署验收与下述本地检查分开。

备份 Schema 明确允许 MIME 为 null，正式版导出器会保留该值，分片恢复原本回退为 `application/octet-stream`。拒绝这个安全回退会使合法旧备份无法恢复，却无助于阻断 XSS；下载边界由读取时的 MIME 校验保证。

图片 MIME 比较忽略大小写及参数，但入库 MIME 及其参数继续保持原值。校验无需改写存储值，剥离参数反而会丢失 SVG `charset` 等编码信息。

本地浏览器检查发现一个解析差异：以图片/音频类型开头的值，可以在未加引号的逗号后追加 HTML 类型；原先按第一个分号截取的校验会允许内联输出，Chromium 即使收到 `nosniff` 仍会当作 HTML 解析。改用可跨运行时使用的 `content-type@3.1.1` 解析和格式化完整字段，不再拆字符串判断。去空白或解析前，先校验原字段只含 HTAB、可见 ASCII 及 obs-text；其他控制字符、DEL 及非字节字符一律拒绝，即使藏在会被忽略或重复的参数中。兼容风险是多类型或无法安全格式化的声明会被拒绝，响应头的大小写和引号形式可能规范化；合法 SVG 编码参数及已存备份元数据保留。回退会恢复这个绕过，回滚只涉及代码及依赖，不需要迁移数据。
