# 保留信息图同步期间的草稿

## 问题与范围

- 信息图编辑器把每次收到的笔记属性直接作为下次保存基线，却不协调屏幕中的文档。远端更新可能不可见，随后旧图形却带着远端新版本号和哈希上传。
- 工作区使用原始笔记 ID 作为编辑器键。临时 ID 映射到服务端 ID 时会重建编辑器，丢弃仍在等待自动保存的输入。修复前的浏览器回归已复现空闲远端刷新失效和标题回退。
- 本地保存原本已经捕获提交时的快照。保留该行为；延迟回执不得确认后续编辑，也不得替换已经保存到本地的后继草稿。

## 修复与风险

- 复用现有逻辑编辑器身份辅助函数。真正切换笔记时重置编辑器；ID 映射时保留输入、焦点、对话和画布。
- 分离已保存快照与同步元数据。本设备回执只推进版本号、哈希和时间，忽略陈旧或其他笔记的快照。真正的远端更新在空闲时应用；有草稿、生成任务或行内编辑时暂缓，不采用远端并发基线。
- 草稿回到原始基线后继续应用暂缓的更新。把冲突草稿保存到本地，不会解除保护或默许覆盖远端。
- 异步本地保存回执绑定其仍挂载的编辑器，保留更新的已确认版本，只确认本次提交的快照。在 AntV 提交行内文字前跟踪正在进行的编辑。
- 产品改动仅涉及 Web/桌面共用信息图编辑器及工作区挂载方式，不修改数据库结构、同步协议、原生宿主、安装器或升级器。撤销这些产品代码即可回滚，无需迁移。

## 验证边界

- 定向单元测试覆盖陈旧回执、已存入本地的后继草稿、真正的远端修改、对话和会话快照、标签规范化。
- 浏览器回归使用真实本地 API 和存储，覆盖：延迟回执期间编辑标题、标签和行内文字并重开；空闲远端更新及冲突草稿；临时 ID 映射、焦点和重开；已入本地队列的后继草稿收到旧回执。
- 同时运行已有文本和图表同步回归。必需检查：`bun run typecheck`、`bun run typecheck:mobile`、`bun run build:web`。
- 浏览器结果不等于 Windows/macOS/Linux 原生功能、原生旧版到新版链路、安装器或自动升级兼容性验证。本次尚未完成这些原生验证。
