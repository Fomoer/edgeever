# Issue 650 desktop scheduled backup implementation scope

[简体中文](2026-10-23-desktop-scheduled-backup.zh-CN.md)

## Problem and outcome

Implement [Issue #650](https://github.com/tianma-if/edgeever/issues/650) following the [scheduled backup and encrypted recovery design](../desktop-scheduled-backup-design.md). Desktop saves the current account's synchronized knowledge base to a chosen local directory, optionally password-encrypted, and restores it to a new instance without the original instance.

Changes affect desktop background work, shared archives, settings and restore entry points, backup reads, and a new migration. The main risks are write disruption by revision triggers, unreadable archives, plaintext disclosure, and accidental backup deletion. Disabling stops new tasks and keeps files; application rollback retains additive database structures and faulty triggers require a subsequent corrective migration. Validate old-database upgrades, platform directories/credentials, and recovery separately.

When a resource-restore request returns 503, archive consumer errors are rewritten as `invalidZip`, and desktop IPC then drops the HTTP status. Preserve the real failure and record its request diagnostics through the existing desktop log. The main risks are error-classification regressions and sensitive diagnostic fields. Keep ZIP-reader failures classified as invalid archives and use selected fields plus existing redaction. Reverting this item restores the old error path without changing archives or restored data.

An empty Worker behind local Wrangler 4.112.0 also returned 503 at a fixed five-second cadence. Its development proxy has an idle-connection race and misclassifies the error source. Use the repository's existing Bun dependency-patch mechanism to repair local forwarding without retrying restore writes. The risk is local-proxy compatibility; limit connection changes to plain loopback HTTP, preserve remote/WebSocket behavior, and roll back by removing the patch and its package/lockfile registration. Keep running services unchanged; actual business restore requires user acceptance after restarting the development service.

Desktop has duplicate export/backup entry points, no direct actions on completed archives, and creates redundant archives for unchanged data. Unify backup and restore while retaining one-off plain/encrypted output and separating source checks from actual archive creation. Risks are name collisions, file ownership and incorrect skipping; bind operations to the current backup set and use the existing source-revision protocol plus an available previous archive. Rollback does not migrate or rename old archives. Validate in isolated directories without operating on user instances, processes or files.

Expanding backup settings adds a vertical scrollbar, narrowing the card and rewrapping content; settings below the archive list are also hard to find. Move the collapsed settings below status and above history, and reserve scrollbar space in both wide and narrow settings-page scroll containers. Risk is limited to spacing and narrow-window layout. Reverting these two layout changes restores the previous arrangement without changing collapsed defaults, configuration, backup or restore behavior. Check actual expanded/collapsed widths, keyboard operation and narrow-window rendering.

The contribution branch starts from current official main and carries only this feature, not deployment-fork snapshot history. Give the new backup migration an unused increasing number, retaining every published upstream migration, notebook-appearance field and locale catalog. Integration risks are migration ordering, dropped archive fields and regressions in existing callers. Validate isolated old-database upgrades and old/new export/restore paths; rolling back code must not delete data or additive migration structures. Keep the original development checkout and user instances unchanged. Review B01–B19 for correctness, necessary complexity and actual UI behavior; record each evidence-backed behavior fix before implementing it.

## Unchanged boundaries

- Preserve executed migrations, synchronization protocol, note IDs and permissions. Old backups/json, ordinary Web manual ZIP, bounded browser fallback and SQLite recovery keep their existing conditions of use.
- No WebDAV/S3 uploads, OS service after app exit, encrypted Web entry points, native mobile UI or whole-instance image; no installer/update/version/release changes.
- Do not operate on existing user instances, production databases, installed desktop apps or users' cloud-drive data. Verify with isolated directories and test instances; commit/push only the contribution branch and create a PR, without a release or deployment.
- Add only shared components, dependencies, packaging inclusions, fixtures and test adapters needed for the listed behavior. Cloudflare and Docker retain shared business logic.
